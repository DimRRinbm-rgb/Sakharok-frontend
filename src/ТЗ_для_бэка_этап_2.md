# СахарОК — ТЗ для бэкенда, этап 2

Стек прежний: Node.js + Express + SQLite. На этапе 1 авторизации не было, теперь она нужна:
у каждого пользователя свои записи, лекарства и приёмы у врача.

Фронт уже готов и ждёт ровно такие запросы и ответы. Адрес сервера — `http://localhost:3000/api`,
на бэке должен быть подключён пакет `cors`.

---

## Часть 1. Регистрация и вход (по-настоящему)

### Пакеты
```
npm install bcryptjs jsonwebtoken
```

### Таблица пользователей
```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  full_name TEXT NOT NULL,
  login TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,      -- НЕ пароль, а хеш!
  birth_date TEXT NOT NULL,         -- "2008-05-14"
  gender TEXT NOT NULL,             -- male | female
  diabetes_type TEXT NOT NULL,      -- type1 | type2 | gestational | other
  created_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```

### POST /api/auth/register
Тело:
```json
{
  "fullName": "Иванов Алексей Петрович",
  "login": "alexey",
  "password": "secret123",
  "birthDate": "2008-05-14",
  "gender": "male",
  "diabetesType": "type1"
}
```
Что делает: проверяет поля, хеширует пароль, сохраняет пользователя, сразу выдаёт токен.

Успех — `201`:
```json
{
  "token": "eyJhbGciOi...",
  "user": {
    "id": 1,
    "fullName": "Иванов Алексей Петрович",
    "login": "alexey",
    "birthDate": "2008-05-14",
    "gender": "male",
    "diabetesType": "type1"
  }
}
```
**В ответе никогда не должно быть пароля или хеша.**

Ошибки (всегда в виде `{ "error": "текст" }`, фронт показывает этот текст пользователю):
- `400` — "Введите ФИО", "Логин должен быть не короче 3 символов", "Пароль должен быть не короче 6 символов",
  "Некорректная дата рождения", "Некорректный пол", "Некорректный тип диабета"
- `409` — "Такой логин уже занят"

### POST /api/auth/login
Тело: `{ "login": "alexey", "password": "secret123" }`
Успех — `200`, ответ такой же, как у регистрации (`token` и `user`).
Ошибка — `401`: `{ "error": "Неверный логин или пароль" }`
(текст один и тот же и для «нет такого логина», и для «неверный пароль» — так безопаснее).

### Как это сделать
```js
const bcrypt = require("bcryptjs");
const jwt = require("jsonwebtoken");

// Секрет для подписи токенов. Хранить в файле .env, в git НЕ класть!
const SECRET = process.env.JWT_SECRET || "поменяйте-этот-секрет";

// Регистрация
const hash = await bcrypt.hash(password, 10);
// INSERT INTO users (...) VALUES (..., hash, ...)
const token = jwt.sign({ userId: newUser.id }, SECRET, { expiresIn: "7d" });

// Вход
// SELECT * FROM users WHERE login = ?
const ok = await bcrypt.compare(password, user.password_hash);
if (!user || !ok) return res.status(401).json({ error: "Неверный логин или пароль" });
```

### Проверка токена (middleware)
Подключается ко ВСЕМ маршрутам `/api/measurements`, `/api/medications`, `/api/appointments`.
Фронт присылает заголовок `Authorization: Bearer <token>`.
```js
function auth(req, res, next) {
  const header = req.headers.authorization || "";
  const token = header.replace("Bearer ", "");
  try {
    const data = jwt.verify(token, SECRET);
    req.userId = data.userId;   // дальше во всех запросах используем req.userId
    next();
  } catch (err) {
    res.status(401).json({ error: "Нужно войти" });
  }
}

app.use("/api/measurements", auth);
app.use("/api/medications", auth);
app.use("/api/appointments", auth);
```
При ответе `401` фронт сам стирает токен и открывает страницу входа.

### Что поменять в уже готовых маршрутах измерений
1. В таблицу `measurements` добавить `user_id INTEGER NOT NULL`
   (проще всего удалить старый файл базы и создать таблицы заново).
2. При создании записи: `user_id = req.userId`.
3. Во всех запросах (получить, изменить, удалить, последнее, за период) добавить `AND user_id = ?` —
   иначе один пользователь увидит чужие записи. Если чужая запись по id — отвечать `404`.

## Часть 2. Лекарства

```sql
CREATE TABLE medications (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  name TEXT NOT NULL,
  doses INTEGER NOT NULL,     -- сколько доз за один приём
  time TEXT NOT NULL,         -- "08:30"
  created_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```

| Метод | Адрес | Что делает |
|---|---|---|
| GET | /api/medications | все лекарства пользователя (массив), по возрастанию времени |
| POST | /api/medications | создать, вернуть созданную запись **с id** (`201`) |
| PUT | /api/medications/:id | изменить, вернуть обновлённую запись |
| DELETE | /api/medications/:id | удалить |

Объект лекарства:
```json
{ "id": 1, "name": "Метформин", "doses": 2, "time": "08:30" }
```
Валидация: `name` не пустое; `doses` целое от 1 до 20; `time` в формате `ЧЧ:ММ`.
Ошибка — `400`: `{ "error": "Некорректное количество доз" }`.

## Часть 3. Записи к врачу

```sql
CREATE TABLE appointments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  doctor TEXT NOT NULL,       -- "Эндокринолог"
  date TEXT NOT NULL,         -- "2026-10-08"
  time TEXT NOT NULL,         -- "10:30"
  place TEXT,                 -- может быть пустым
  note TEXT,                  -- может быть пустой
  created_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```

| Метод | Адрес | Что делает |
|---|---|---|
| GET | /api/appointments | все записи пользователя (массив), по возрастанию даты и времени |
| POST | /api/appointments | создать, вернуть созданную запись **с id** (`201`) |
| PUT | /api/appointments/:id | изменить, вернуть обновлённую запись |
| DELETE | /api/appointments/:id | удалить |

Объект записи:
```json
{ "id": 1, "doctor": "Эндокринолог", "date": "2026-10-08", "time": "10:30",
  "place": "Поликлиника, кабинет 204", "note": "Взять результаты анализов" }
```
Валидация: `doctor`, `date` (`ГГГГ-ММ-ДД`), `time` (`ЧЧ:ММ`) обязательны.

**Автоматические записи.** Если бэк сам создаёт приём (например, по расписанию или после анализов),
достаточно добавить строку в таблицу `appointments` с нужным `user_id`.
Фронт показывает все записи из одного списка, отдельной логики не нужно.

## Проверка в Postman
1. `POST /api/auth/register` → скопировать `token` из ответа.
2. В остальных запросах: вкладка Authorization → Bearer Token → вставить токен.
3. Без токена любой `/api/measurements`, `/api/medications`, `/api/appointments` должен отвечать `401`.
4. Зарегистрировать второго пользователя и убедиться, что он не видит записи первого.

## Безопасность — коротко
- Пароль хранится только как хеш `bcrypt`; в ответах и логах его нет.
- Секрет `JWT_SECRET` лежит в `.env`, файл `.env` добавлен в `.gitignore`.
- Всё, что пришло с фронта, проверяется на бэке заново (проверки на фронте — только для удобства).
- При выкладке на настоящий сервер нужен HTTPS, иначе пароль уходит открытым текстом.
